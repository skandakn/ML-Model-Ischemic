2. Formal Temporal Architecture & Window Terminology Correction

[!IMPORTANT] Documentation Correction: Previous draft reports inadvertently described the sliding windows as 'non-overlapping'. Because the window span is 300 seconds and the advance stride is 60 seconds, each consecutive window shares 240 seconds (80%) of physiological waveform with its predecessor. The correct, precise clinical terminology is:
'Overlapping sliding windows with a 60-second stride.'

Temporal Window Architecture (Total Timeline Span = 900 seconds / 15 minutes):
+-----------------------+-----------------------+-----------------------+
|   T_obs (300 s)       |   T_gap (300 s)       |   T_target (300 s)    |
|   [t, t + 300)        |   [t + 300, t + 600)  |   [t + 600, t + 900)  |
|   Model Feature Slice |   Enforced Lead Time  |   Clinical Target     |
+-----------------------+-----------------------+-----------------------+
      |---> 60s Stride ---> Next Window [t + 60, t + 960)

Mathematical & Clinical Integrity Rules:

  1. Feature Scope: Features are extracted strictly inside $[t, t + 300)$. Zero data from $t \ge t + 300$ is accessible.
  2. Lead-Time Guarantee: A strict 5-minute blank gap ($T_{\text{gap}} = 300\text{ s}$) separates predictor observations from the target horizon.
  3. Consecutive Run Target Definition: $y=1$ requires $\text{max_consecutive}(ST_II \le -1.0\text{ mm}) \ge 60\text{ s}$ inside $T_{\text{target}}$, with NO sustained ST depression active during $T_{\text{obs}}$ or $T_{\text{gap}}$.

5. Statistical Viability Assessment: Is a Single 70/15/15 Split Defensible?

[!WARNING] HIGH STATISTICAL UNCERTAINTY IN A SINGLE 15% TEST PARTITION: 1. Extreme Case-Level Sparsity: With only 8 positive patients across the entire 100-case cohort, a 15% partition (15 cases) contains only 1 to 2 positive patients. 2. Sensitivity Volatility: If a model correctly flags 1 of 2 test patients, patient-level sensitivity is 50%. If it misses that 1 patient, sensitivity plunges to 0%. If there is only 1 positive patient in the test set, sensitivity is binary (100% or 0%). Such metrics are clinically uninterpretable and fail to demonstrate robust generalization. 3. Window Count Instability: Because different patients have differing numbers of early-warning opportunities (e.g. Case 2085 has 2 positive windows, while Case 3280 has 9 windows), the test partition positive window count fluctuates between 5 and 17 windows purely based on random seed selection. 4. Rigorous Conclusion: A single, static 70/15/15 train/validation/test split is statistically fragile for model selection and threshold calibration. Relying solely on a single 15-case test set would produce unacceptably noisy performance benchmarks.

Scientific Advantages of Grouped 5-Fold Cross-Validation:

  1. Complete Cohort Evaluation: In 5-fold CV, all 8 positive cases (and all 48 positive windows) are evaluated in out-of-fold validation. No positive case is locked away uninspected.
  2. Strict Patient Isolation: In every fold, training and validation sets are strictly disjoint at the patient level ($ ext{Train Cases} \cap ext{Val Cases} = \emptyset$). Zero window leakage can occur.
  3. Pooled Out-of-Fold Estimation: Out-of-fold predictions from all 5 folds can be aggregated to compute cohort-wide PR-AUC, AUROC, and Brier calibration scores across all 100 patients, yielding substantially narrower confidence intervals.

7. Recommended Locked Test Set Strategy

To balance unbiased final benchmark testing with maximal development-time stability, the following two-tier architecture is recommended:

  1. Tier 1 — Development Set (80 Cases, 5-Fold Grouped CV): - 80 cases (40 Cohort A, 40 Cohort B) containing 6 positive cases and 74 negative cases. - Dedicated to feature selection, architecture comparison (Matrix A vs Matrix B), hyperparameter tuning, and decision threshold calibration via 5-fold StratifiedGroupKFold.
  2. Tier 2 — Locked Benchmark Test Set (20 Cases, Sealed): - 20 cases (10 Cohort A, 10 Cohort B) containing exactly 2 stratified positive cases (1 from Cohort A, 1 from Cohort B) and 18 negative cases. - Completely Sealed: Never accessed during preprocessing decisions, feature pruning, model selection, or hyperparameter optimization. - Evaluated exactly once at the conclusion of modeling to verify generalization to unseen patients.
